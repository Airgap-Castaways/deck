# 소개

## deck이란

`deck`은 에어갭(망분리), 네트워크 단절을 비롯해 운영상 제약이 큰 환경을 위한 구조화된 워크플로 도구입니다. 오프라인 Kubernetes 부트스트랩, 패키지 설치, 호스트 구성을 처리하느라 끝없이 불어나는 셸 스크립트를, 자기 완결적 번들에 담긴 타입 지정·검증된 스텝으로 대체합니다.

이 도구는 정작 작업을 수행하는 시점에 인터넷 접속이나 도달 가능한 컨트롤 플레인을 전제할 수 없는 운영자를 위해 설계되었습니다. 규제가 적용되는 데이터 센터, 산업용 엣지 사이트, 정부 네트워크처럼 "대상 장비에 SSH로 접속해 인터넷에서 내려받는" 방식이 통하지 않는 모든 환경, deck은 바로 이런 곳을 위해 만들어졌습니다.

단 하나의 정적 `deck` 바이너리가 작성, 검증, 아티팩트 수집, 번들링은 물론 대상 장비에서의 로컬 실행까지 모두 담당합니다. 대상 머신에는 미리 설치된 런타임도, 네트워크 역방향 연결도 필요하지 않습니다. 필요한 모든 것은 번들과 함께 이동합니다.

## 핵심 개념

deck은 오프라인 작업을 뚜렷이 구분되는 세 단계로 나눕니다.

- **Prepare** — 아직 인터넷에 접속할 수 있는 동안 `deck prepare`가 워크플로에 필요한 모든 아티팩트를 내려받습니다. 컨테이너 이미지, OS 패키지, 바이너리 파일이 여기에 해당하며, 이들은 로컬 `outputs/` 트리에 저장됩니다.
- **Bundle** — `deck bundle build`는 워크플로 정의, 준비된 아티팩트, 그리고 `deck` 바이너리 자체를 하나의 `bundle.tar`로 묶습니다. 이 아카이브는 USB 드라이브나 배스천을 거쳐, 혹은 사이트가 허용하는 방식으로 망분리 경계를 넘겨 전달하는 파일입니다.
- **Apply** — 연결이 끊긴 대상 장비에서 `deck apply`가 워크플로를 로컬로 실행합니다. SSH도, 컨트롤러도, 외부로의 역방향 연결도 필요 없습니다. 머신은 전달받은 번들에서 스텝을 직접 실행합니다.

이 prepare → bundle → apply 라이프사이클이 핵심 개념입니다. 각 단계는 명시적이며, 번들을 사이트로 들고 가기 전에 검토할 수 있습니다.

## 왜 셸 스크립트로는 부족한가

셸 스크립트는 시작하기 쉽고 거의 어디서나 실행됩니다. 하지만 작업 규모가 커지면 한계가 드러납니다.

- **타입 지정 스텝은 의도를 드러냅니다.** `InstallPackage` 스텝은 스펙을 읽기도 전에 무슨 일이 일어날지 검토자에게 알려줍니다. `rpm`이나 `apt` 명령 블록은 그렇지 못합니다.
- **사전 검증으로 실수를 일찍 잡습니다.** `deck lint`는 연결된 환경을 떠나기 전에 워크플로 구조와 모든 스텝 스키마를 검사합니다. 오타나 누락된 필드를 망분리 환경 안에서 발견하면 큰 비용이 따릅니다.
- **번들은 자기 완결적이며 검증할 수 있습니다.** 워크플로 정의, 필요한 모든 아티팩트, 그리고 `deck` 바이너리가 하나의 아카이브로 함께 전달됩니다. 현장에서 풀어볼 때 빠진 의존성에 발목 잡힐 일이 없습니다.
- **apply는 재개할 수 있습니다.** 실행이 도중에 멈추더라도 `deck apply`는 처음부터 다시 시작하지 않고 마지막으로 완료된 단계부터 이어갑니다. 셸 스크립트로는 별도의 기록 관리 없이 이런 동작을 구현할 수 없습니다.

## 무엇이 들어 있는가

deck은 작고 집중된 표면적을 갖춘 단일 바이너리로 제공됩니다.

- **타입 지정 스텝 종류** — 파일 쓰기, 패키지 설치, 서비스 관리, sysctl, 커널 모듈, 컨테이너 이미지 로딩, kubeadm 라이프사이클 등을 다룹니다. 워크플로를 초안 작성하거나 검토할 때는 작성 보조 도구인 [`deck ask`](ask.md)를 활용하십시오.
- **CEL `when` 조건** — 런타임에 평가되는 타입 지정 표현식으로 어떤 스텝이든 건너뛰거나 보호할 수 있습니다.
- **단계와 병렬 처리** — 이름이 붙은 단계는 작업을 한눈에 읽히게 하고, `parallelGroup`은 한 단계 안에서 서로 독립적인 스텝을 동시에 실행합니다.
- **변수와 템플릿화** — 공유 `vars.yaml`과 호출마다 지정하는 `--var` 오버라이드를 통해 사이트별 값을 스텝 정의에서 분리합니다.
- **재개 가능한 apply 상태** — 단계 수준의 상태가 이미 실행된 내용을 추적하므로, 멈춘 apply를 안전하게 이어갈 수 있습니다.
- **내장 콘텐츠 서버** — `deck server up`은 준비된 번들 루트를 망분리 환경 안에서 HTTP로 노출합니다. 여러 노드가 공유된 로컬 소스에서 내려받아야 할 때 유용합니다.
- **AI 작성 보조 도구** — `deck ask`는 LLM 기반 보조 도구로 워크플로를 초안 작성하고, 설명하고, 검토하는 실험적 옵트인 기능입니다. 표준 `deck` 바이너리에 포함되어 있으며, 모델에 접근할 수 없을 때는 기능을 우아하게 낮춥니다.
