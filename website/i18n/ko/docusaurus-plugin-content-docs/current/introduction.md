# 소개

## deck이란

`deck`은 에어갭(망분리), 네트워크 단절, 운영 제약이 있는 환경을 위한 구조화된 워크플로 도구입니다. 오프라인 Kubernetes 부트스트랩, 패키지 설치, 호스트 구성을 진행하다 보면 셸 스크립트가 계속 쌓이는데, deck은 이를 타입이 지정되고 검증되는 스텝으로 바꿔 자체 완결형 번들에 담습니다.

이 도구는 정작 절차를 실행하는 시점에 인터넷 접속이나 도달 가능한 컨트롤 플레인을 기대할 수 없는 운영자를 위해 설계되었습니다. 규제가 적용되는 데이터 센터, 산업용 엣지 사이트, 정부 네트워크처럼 "대상에 SSH로 접속해 인터넷에서 내려받는" 방식이 통하지 않는 환경, deck은 바로 이런 환경을 겨냥합니다.

정적으로 링크된 단일 `deck` 바이너리 하나가 작성, 검증, 아티팩트 수집, 번들링, 대상에서의 로컬 실행까지 모두 처리합니다. 대상 머신에는 미리 설치된 런타임도, 외부로 향하는 역방향 연결도 필요하지 않습니다. 필요한 모든 것이 번들과 함께 이동하기 때문입니다.

## 핵심 아이디어

deck은 오프라인 작업을 뚜렷이 구분되는 세 단계로 나눕니다.

- **준비(Prepare)**: 아직 인터넷에 접속할 수 있을 때 `deck prepare`가 워크플로에 필요한 모든 아티팩트, 즉 컨테이너 이미지, OS 패키지, 바이너리 파일을 내려받습니다. 이렇게 받은 아티팩트는 로컬 `outputs/` 트리에 저장됩니다.
- **번들(Bundle)**: `deck bundle build`가 워크플로 정의와 준비된 아티팩트, 그리고 `deck` 바이너리 자체를 하나의 `bundle.tar`로 묶습니다. 이 아카이브가 바로 USB 드라이브나 배스천 경유 등 사이트가 허용하는 어떤 방식으로든 에어갭을 넘겨 전달하는 대상입니다.
- **적용(Apply)**: 네트워크가 단절된 대상에서 `deck apply`가 워크플로를 로컬에서 실행합니다. SSH도, 컨트롤러도, 외부로 향하는 역방향 연결도 없습니다. 머신은 전달받은 번들에서 곧바로 스텝을 실행합니다.

prepare → bundle → apply로 이어지는 생애주기가 바로 핵심 아이디어입니다. 각 단계는 명시적이며, 번들을 사이트로 반입하기 전에 검토할 수 있습니다.

## 셸 스크립트로는 왜 안 되는가

셸 스크립트는 시작하기 쉽고 거의 어디서나 실행됩니다. 문제는 절차가 커질수록 드러납니다.

- 타입이 지정된 스텝은 의도를 분명히 드러냅니다. `InstallPackage` 스텝은 검토자가 스펙을 읽기도 전에 무슨 일이 일어날지 알려주지만, `rpm`이나 `apt` 명령이 나열된 블록은 그렇지 못합니다.
- 사전 검증은 실수를 일찍 잡아냅니다. `deck lint`는 연결된 환경을 떠나기 전에 워크플로 구조와 모든 스텝 스키마를 검사합니다. 에어갭 안에서 오타나 누락된 필드를 발견하려면 치르는 비용이 크기 때문입니다.
- 번들은 자체 완결형이며 검증할 수 있습니다. 워크플로 정의와 필요한 모든 아티팩트, `deck` 바이너리가 하나의 아카이브로 함께 전달되므로, 현장에서 압축을 풀 때 뜻밖에 의존성이 빠지는 일이 없습니다.
- 적용은 재개할 수 있습니다. 실행이 중간에 멈추더라도 `deck apply`는 처음부터 다시 시작하지 않고 마지막으로 완료된 단계부터 이어갑니다. 셸 스크립트로 같은 동작을 구현하려면 별도의 상태 관리가 필요합니다.

## 무엇이 들어 있는가

deck은 작고 집중된 표면만 노출하는 단일 바이너리로 배포됩니다.

- **타입이 지정된 스텝 종류**: 파일 쓰기, 패키지 설치, 서비스 관리, sysctl, 커널 모듈, 컨테이너 이미지 로딩, kubeadm 생애주기 등을 다룹니다. 워크플로를 작성하거나 검토할 때는 [`deck ask`](ask.md)를 작성 보조 도구로 활용하십시오.
- **CEL `when` 조건**: 런타임에 평가되는 타입 지정 표현식으로 어떤 스텝이든 건너뛰거나 가드할 수 있습니다.
- **단계와 병렬 처리**: 이름이 붙은 단계는 절차를 한눈에 읽히게 하고, `parallelGroup`은 한 단계 안에서 서로 독립적인 스텝을 동시에 실행합니다.
- **변수와 템플릿화**: 공유되는 `vars.yaml`과 호출별 `--var` 오버라이드를 함께 써서 사이트별 값을 스텝 정의 밖으로 뺍니다.
- **재개 가능한 적용 상태**: 단계 수준의 상태가 이미 실행된 부분을 추적하므로, 멈춘 적용을 안전하게 이어갈 수 있습니다.
- **내장 콘텐츠 서버**: `deck server up`은 준비된 번들 루트를 에어갭 안에서 HTTP로 노출합니다. 여러 노드가 공유된 로컬 소스에서 내려받아야 할 때 유용합니다.
- **AI 작성 보조 도구**: `deck ask`는 LLM 기반 어시스턴트로 워크플로를 초안 작성하고, 설명하고, 검토하는 실험적 옵트인 도구입니다. 표준 `deck` 바이너리에 포함되어 있으며, 모델에 접근할 수 없을 때는 무리 없이 기능을 낮춰 동작합니다.
