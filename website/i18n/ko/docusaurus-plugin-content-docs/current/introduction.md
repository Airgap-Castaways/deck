# 소개

## deck란

`deck`는 에어갭(망분리), 비연결, 운영 제약이 있는 환경을 위한 구조화된 워크플로 도구입니다. 오프라인 Kubernetes 부트스트랩, 패키지 설치, 호스트 구성 주위에 쌓여만 가는 셸 스크립트를, 자체 완결적 번들에 담긴 타입 지정·검증된 스텝으로 대체합니다.

이 도구는 실제로 절차를 실행하는 시점에 인터넷 접근이나 도달 가능한 컨트롤 플레인을 가정할 수 없는 운영자를 위해 설계되었습니다. 규제 대상 데이터센터, 산업용 엣지 사이트, 정부망, 그리고 "대상 장비에 SSH로 접속해 인터넷에서 받아온다"가 선택지가 아닌 모든 환경 — 이것이 deck가 만들어진 환경입니다.

단일 정적 `deck` 바이너리가 작성, 검증, 아티팩트 수집, 번들링, 대상에서의 로컬 실행까지 모든 것을 처리합니다. 대상 장비에는 사전 설치된 런타임도, 네트워크 회신 경로도 필요하지 않습니다. 필요한 모든 것은 번들과 함께 이동합니다.

## 핵심 개념

deck는 오프라인 작업을 세 개의 뚜렷한 단계로 나눕니다:

- **준비(Prepare)** — 아직 인터넷 접근이 가능할 때, `deck prepare`가 워크플로에 필요한 모든 아티팩트를 다운로드합니다: 컨테이너 이미지, OS 패키지, 바이너리 파일. 이들은 로컬 `outputs/` 트리에 저장됩니다.
- **번들(Bundle)** — `deck bundle build`는 워크플로 정의, 준비된 아티팩트, 그리고 `deck` 바이너리 자체를 단일 `bundle.tar`로 패키징합니다. 이것이 USB 드라이브, 베스천 경유, 또는 사이트에서 허용하는 어떤 방식으로든 에어갭을 가로질러 전송하는 아카이브입니다.
- **적용(Apply)** — 비연결 대상에서 `deck apply`가 워크플로를 로컬로 실행합니다. SSH도, 컨트롤러도, 외부 회신 경로도 없습니다. 장비는 전달받은 번들에서 직접 스텝을 실행합니다.

준비 → 번들 → 적용 라이프사이클이 핵심 개념입니다. 각 단계는 명시적이며, 번들을 사이트로 가져가기 전에 검토할 수 있습니다.

## 왜 셸 스크립트가 아닌가

셸 스크립트는 시작하기 쉽고 거의 어디서나 실행됩니다. 하지만 절차가 커지면서 문제가 됩니다:

- **타입 지정된 스텝은 의도를 드러냅니다.** `InstallPackage` 스텝은 검토자가 스펙을 읽기 전에 무슨 일이 일어날지 알려줍니다. `rpm`이나 `apt` 명령 블록은 그렇지 않습니다.
- **사전 검증이 실수를 일찍 잡아냅니다.** `deck lint`는 연결된 환경을 떠나기 전에 워크플로 구조와 모든 스텝 스키마를 검사합니다. 에어갭 안에서 오타나 누락된 필드를 발견하는 것은 비용이 큽니다.
- **번들은 자체 완결적이며 검증 가능합니다.** 워크플로 정의, 필요한 모든 아티팩트, 그리고 `deck` 바이너리가 하나의 아카이브에 함께 실립니다. 현장에서 압축을 풀 때 예기치 못한 누락 의존성이 없습니다.
- **적용은 재개 가능합니다.** 실행이 중간에 멈추면, `deck apply`는 처음부터 다시 시작하지 않고 마지막으로 완료된 단계부터 재개합니다. 셸 스크립트는 별도의 기록 관리 없이는 이에 상응하는 기능을 제공하지 않습니다.

## 무엇이 들어 있나

deck는 작고 집중된 표면적을 가진 단일 바이너리로 제공됩니다:

- **42가지 타입 지정 스텝 종류** — 파일 쓰기, 패키지 설치, 서비스 관리, sysctl, 커널 모듈, 컨테이너 이미지 로딩, kubeadm 라이프사이클 등을 포괄합니다. 워크플로를 작성하거나 검토할 때 작성 보조 도구로 [`deck ask`](ask.md)를 사용하세요.
- **CEL `when` 조건** — 런타임에 평가되는 타입 지정 표현식으로 어떤 스텝이든 건너뛰거나 가드할 수 있습니다.
- **단계와 병렬성** — 명명된 단계는 절차를 한눈에 읽을 수 있게 하며, `parallelGroup`은 단계 내에서 독립적인 스텝을 동시에 실행합니다.
- **변수와 템플릿팅** — 공유 `vars.yaml`에 호출별 `--var` 오버라이드를 더해 사이트별 값을 스텝 정의에서 분리합니다.
- **재개 가능한 적용 상태** — 단계 수준의 상태가 이미 실행된 것을 추적하므로, 멈춘 적용을 안전하게 이어갈 수 있습니다.
- **내장 콘텐츠 서버** — `deck server up`은 준비된 번들 루트를 에어갭 안에서 HTTP로 노출하며, 여러 노드가 공유 로컬 소스에서 받아와야 할 때 유용합니다.
- **AI 작성 보조 도구** — `deck ask`는 LLM 기반 보조 도구를 사용해 워크플로를 초안 작성, 설명, 검토하는 실험적 옵트인 헬퍼입니다. 표준 `deck` 바이너리의 일부이며, 모델 접근이 불가능할 때 우아하게 동작을 낮춥니다.
